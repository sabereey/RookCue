# RookCue 0.1.0-beta.9

## English

This prerelease makes local cross-agent installation and task handoff repeatable.
Grok, Claude Code and eligible Codex installations can share one skill; existing
Codex plugins remain app-managed until explicitly migrated.

Task handoffs distinguish execution progress from task lifecycle. Ready artifacts
can wait for user acceptance while the task remains open. Handoffs record the
long-term goal, current scope, per-step executor/evidence, artifacts, constraints,
tool dependencies and next action. Existing checkpoints remain readable; reading
does not migrate them. Reported agent attribution is not authenticated identity.

### Download and upgrade

- `rookcue-0.1.0-beta.9-plugin.tar.gz`: complete shared skill and Codex plugin.
- `rookcue-0.1.0-beta.9-source.tar.gz`: buildable source and documentation.
- `gmem-0.1.0-beta.9-darwin-arm64.tar.gz`: Apple Silicon macOS executable package.
- `gmem-0.1.0-beta.9-linux-x64.tar.gz`: Linux x64 executable package.
- `SHA256SUMS`: checksums for the delivered archives and install verification.
- `install-verification.json`: disposable fresh-install/beta.8 upgrade evidence.

Ask your agent to install/update from the beta.9 release plugin. It runs the shared
installer with your existing installation authorization and runtime directory.
Keep a custom `ROOKCUE_RUNTIME_HOME` when upgrading. Start a fresh host session.
Codex app-managed plugins must be updated through Codex; connecting Grok/Claude
does not update that plugin cache. Source runtime setup requires Node >=22.12.0
or the bundled private Node bootstrap; native executables have their own package
installation instructions. Windows shared installation is not supported.

No project/personal-data migration is required for this release. New structured
handoffs use `version: 1`, independent of product versions. Older runtimes can
store their free-form snapshot but do not validate or surface the new handoff.
Retain the previous runtime and matching skill for rollback. Do not downgrade
data formats introduced by earlier releases without their documented backup path.
macOS binaries are ad-hoc signed, not Developer ID notarized. CI tests local
loopback synchronization; this release does not claim new physical LAN acceptance.

Documentation correction after publication: the shipped third-party inventory
labels Zod as 4.4.3; the lockfile and packages use 4.6.7. The included Zod license
text is byte-for-byte identical to 4.6.7's license. The inventory label is corrected
on main; the published tag and archives remain unchanged.

## 简体中文

本次预发布完善了本机多 agent 共享安装和任务交接。Grok、Claude Code 和符合条件的
Codex 安装可共用技能；已有 Codex 插件在明确迁移前仍由应用管理。

任务生命周期与实际执行进度分开表达。产物已就绪时可以等待用户验收，同时保持任务
未结项。交接保存长期目标、本轮范围、每一步的执行者与证据、产物、约束、工具依赖及
下一步。旧 checkpoint 继续可读，读取不会自动迁移。执行者字段为记录者声明，不是身份认证。

### 下载与升级

- `rookcue-0.1.0-beta.9-plugin.tar.gz`：完整共享技能和 Codex 插件。
- `rookcue-0.1.0-beta.9-source.tar.gz`：可构建源码和文档。
- `gmem-0.1.0-beta.9-darwin-arm64.tar.gz`：Apple Silicon macOS 可执行程序包。
- `gmem-0.1.0-beta.9-linux-x64.tar.gz`：Linux x64 可执行程序包。
- `SHA256SUMS`：各归档及安装验证文件的校验值。
- `install-verification.json`：临时环境中全新安装及 beta.8 升级的验证结果。

让 agent 从 beta.9 发布的插件安装或升级，沿用已有安装授权和运行时目录。自定义目录
需要保留 `ROOKCUE_RUNTIME_HOME`。升级后开启新会话。应用管理的 Codex 插件需要通过
Codex 更新；更新 Grok/Claude 的共享技能不会刷新该插件缓存。源码运行时需要
Node >=22.12.0 或安装器提供的独立 Node；原生程序的安装方式见包内说明。
共享安装暂不支持 Windows。

本次升级不需要迁移项目或个人数据。新交接格式使用独立的 `version: 1`；旧运行时可保存
自由格式快照，但不会校验或单独展示新交接字段。回退时保留旧运行时及配套技能；更早
版本涉及的数据格式降级仍需遵循其备份流程。macOS 程序为临时签名，未经 Developer ID
公证。CI 同步验证使用本机回环网络，本次发布不宣称新增物理局域网验收。

发布后文档更正：发布包的第三方依赖清单仍将 Zod 标注为 4.4.3；实际锁文件和程序使用
4.6.7，附带的 Zod 许可正文与 4.6.7 逐字节一致。main 已修正清单标注，已发布标签和
归档保持不变。
