# RookCue 路线图

更新于 2026-11-11。

RookCue 帮助使用 Agent 的人从实际工作中积累经验，按需检索，并在新任务遇到相似问题时获得提示。用户掌握自己的数据，经验晋升由本人明确批准。核心 CLI 和现有 Codex 集成采用 GPL-3.0-only。知识展示扩展和未来可能提供的云服务是可选增值方向。参见[许可说明](../LICENSE_POLICY.md)。

## 当前进度

| 能力 | 状态与验收边界 |
| --- | --- |
| 本地核心 | 已实现任务记录、检查点、上下文恢复、复盘、知识审批与晋升、检索、来源追溯、导出校验和导入预览。 |
| Agent 集成 | 现有 Codex 集成已通过私有 Beta 的 Mac 新会话验收。兼容 `gmem`、`growth-memory`、现有插件标识和本地数据目录。 |
| 局域网直连 | 两台 Apple Silicon Mac 已验证显式配对、加密双向同步、冲突处理、删除与中断恢复。两端使用私网 IPv4 直接通信。参见[局域网指南](lan-direct-sync.md)。 |
| 自选存储备份与同步 | 已实现可选的文件系统、NAS 和 S3 兼容存储同步，含加密、显式冲突处理和 S3 条件写入。恢复提供预览，S3 对象列举、删除和清理尚未开放。 |
| 个人成长 | CLI 已支持质量反馈、基于历史的复盘建议、复习安排、能力轨迹、周期报告和方法推荐。真实使用中的任务恢复、经验复用和提示价值仍在验证。 |
| 源码发布 | 首发源码候选已准备，已有类型检查和 611 项测试通过的记录。独立 Git 首提交和公开发布待完成。 |
| 原生发行 | macOS arm64 和 Linux x64 原生 CI 已验证。Mac 安装包的 Developer ID 签名、公证和默认 Gatekeeper 下的新下载验收待完成。 |

## 接下来做什么

1. **建立公开源码的开发基线。** 在独立的 RookCue 仓库提交首发源码，核对许可、第三方声明、安装步骤和安全问题报告入口。由项目所有者确认发布范围后公开。开发入口见[README](../README.md)。
2. **验证任务中的经验提示。** 选一个实际任务，在开工或相关决策前检索已批准经验。命中时提示一条相关经验，附来源及适用条件。没有合适的经验时保持静默。用一次真实命中和本人对提示的反馈验证价值。目前的观察只有一次真实任务检索未命中。
3. **继续真实使用观察，再选首个展示扩展。** 收集任务恢复、重复工作、复用和操作负担的实际反馈。根据反馈决定优先解决的问题，以及知识卡片、成长报告等展示形式是否值得做。扩展范围、接口、许可和价格届时单独决定。
4. **并行完成 Mac 安装包交付。** 为新候选完成签名和公证。用另一台 Apple Silicon Mac 从实际分发渠道下载，核对摘要并验证默认安全设置下的首次启动。源码发布与安装包交付分别验收。参见[原生构建指南](binary-build.md)。

## 原有阶段与后续条件

| 阶段 | 后续条件与范围 |
| --- | --- |
| Phase 0 · 可信开源核心 | 完成源码首发和持续使用验收。核心包含个人数据所有权、检索和可移植性，局域网直连是首版能力。 |
| Phase 1 · 采用与可选展示 | 在多个真实任务和 Agent 中验证核心体验。确认展示需求、兼容性和分发方式后再建设付费展示产品。 |
| Phase 2 · 个人成长 | CLI 能力已实现。继续验证复习、报告和能力历史是否帮助用户理解自己的学习进展。回忆、能力判断和知识审批以本人反馈为准。 |
| Phase 3 · 方法与模板生态 | 核心复盘形成持续使用后，再评估可安装的方法与模板包、兼容性、发现和质量审核。已有五问法、AAR、KPT 和费曼方法。 |
| Phase 4 · 团队和组织 | 个人工作流验证后再评估共享知识、入职、架构决策、事件复盘、权限、留存与审计。个人知识与团队共享资产各有访问边界。 |

结构化 Agent 工具（例如 MCP）是后续集成方向，继续复用 CLI 的证据和人工审批语义。异地跨网直连等待使用需求和成本评估。是否提供官方云服务，取决于用户价值和运营能力。若启动该方向，再明确账号、计费、隐私、加密、恢复、支持和数据退出方案。
