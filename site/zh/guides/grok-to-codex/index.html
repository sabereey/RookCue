如何把 Grok 里的任务交给 Codex 继续

在 Grok 用 RookCue 保存检查点，再用 Codex 打开同一个项目，请它继续上次任务。Codex 可以从检查点读到已完成的工作、相关文件和具体的下一步。

先在同一台 macOS 或 Linux 电脑上把 RookCue 接入 Grok 和 Codex。在两个会话里打开同一个项目目录。下面以检查 30 条样本为例。

在 Grok 保存检查点

先请 Grok 用 RookCue 记录任务。检查完前 10 条样本后，把结果写到项目内的 review.md，再请 Grok 暂停。

用 RookCue 保存检查点。样本 1–10 已检查，结果在 review.md。下一步从第 11 条开始。先暂停，保持任务未结项。

在 Codex 接续同一个任务

用 Codex 新开一个会话，打开同一个项目目录。

用 RookCue 继续上次任务。先读最新检查点，告诉我你会从哪里接着做。

确认 Codex 找到了原任务 ID、能读取 review.md，并准备从第 11 条开始。检查完第 11–20 条后，请它更新结果文件，并在原任务上保存新检查点。

切回 Grok 验证交接

在同一个目录新开 Grok 会话，再请 RookCue 继续任务。任务应沿用原来的 ID，保持未结项，显示已检查 20 / 30 条，下一步从第 21 条开始。如果两个 Agent 都从同一个检查点尝试保存，beta.10 可以拒绝基于旧检查点的写入，让 Agent 重新读取最新进度。

示例使用模拟记录，两个检查点的保存和回读已用 RookCue beta.10 复现。技术细节见任务交接约定和 beta.10 发布说明。

RookCue 将任务记录保存在本地。保存经验需要你批准。
